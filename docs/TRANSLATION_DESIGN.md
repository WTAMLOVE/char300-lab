# 写作内容翻译功能详细设计

> 状态：基础翻译于 0.4.0 实现；手动译文保存、备份扩展及翻译阅读模式于 0.5.0 实现（2026-10-25）。自动化与浏览器验证见第 12 节；真实 AI 服务联调仍需用户自己的密钥。依据 [`TRANSLATION_PLAN.md`](./TRANSLATION_PLAN.md)，局域网部署见 [`LAN_HTTPS.md`](./LAN_HTTPS.md)。

## 1. 已确定的需求

- 用户主动点击后，翻译当前草稿或正在查看的历史版本全文，目标语言为英文。
- 译文忠实、自然、接近日常表达；语境合适时允许少量常见俚语。
- 站点主要供个人在受信任的本地局域网使用，不建立用户账户。
- 可切换 OpenAI、DeepSeek、OpenCode Console 等提供兼容接口的服务。切换通过服务端配置完成，页面不显示密钥。
- 译文只作参考，不写入草稿、原文版本、统计或分享图。翻译结果先留在内存；用户点击“保存译文”后，每篇练习保存一份英文文本，再次手动保存直接覆盖，随本地档案备份恢复。
- 点击翻译或查看已保存译文时进入翻译阅读模式，将中间编辑区与右侧版本链区域整体替换为大面积的原文 / 译文阅读区；提供返回入口恢复原有上下文。
- 不记录译文的版本迭代，不保存来源正文快照、版本关联、模型或时间等元数据；已保存译文不保证对应当前草稿或所选历史版本。

## 2. 现状与设计约束

`src/main.ts` 维护 `view`、`detailMode` 和 `selectedVersionId`，写作模式显示 `DailyEntry.draft`，版本模式显示 `Version.content`。`src/store.ts` 把文章保存在浏览器当前 origin 的 OPFS 或 `localStorage`；备份格式由 `src/backup.ts` 管理。`public/sw.js` 只接管 GET 请求。新增保存能力只在 `DailyEntry` 增加译文文本字段，复用现有存储链路；原文版本结构和写作流程保持原有语义。

**局域网地址影响本地数据能力。** 普通 `http://192.168.x.x` 或 `http://主机名` 通常不属于安全上下文；OPFS 与 Service Worker 要求安全上下文。`http://localhost` 在访问设备自身浏览器中可作为开发例外，但另一台设备通过局域网 IP 访问时不能借用该例外。生产使用应通过受浏览器信任的 HTTPS 地址打开页面；证书需要在实际访问设备上受信任。改用 HTTPS 域名、主机名或端口会改变 origin，已有浏览器档案不会自动出现在新地址，切换前应在旧地址导出 ZIP，在新地址导入验证。

## 3. 架构与部署

```mermaid
flowchart LR
  U[浏览器：写作页] -->|点击后 POST 正文| G[同源 /api/translate]
  G -->|凭服务端密钥调用| P[所配置的 AI 服务]
  P -->|译文| G
  G -->|纯文本结果| U
  U -->|原文保存及手动保存译文| S[浏览器 OPFS / localStorage]
```

生产部署：Caddy 的 `char300.com` 站点块使用 `tls internal`，由本地 CA 为**整个站点域名**签发证书。Caddy 将所有路径代理到仅监听 `127.0.0.1:8787` 的 `pnpm run start` 服务；Node 服务提供 Vite 构建后的页面、静态资源和 `/api/translate`。浏览器统一访问 `https://char300.com`，服务端配置 `APP_ORIGIN=https://char300.com`。局域网 DNS/hosts 将域名映射到服务器局域网 IP，访问设备信任 Caddy 根证书。Caddy 只允许局域网访问，不设置公网端口映射。API 进程的密钥只在服务器环境变量或服务器本地受保护的配置中，不进入 Vite 构建、浏览器存储、仓库或日志。局域网内其他设备仍可能请求此接口，因此保留输入限制、简单限流和服务商用量提醒。若局域网并非完全受信任，应另加访问保护；本设计不包含账户系统。具体操作见 [`LAN_HTTPS.md`](./LAN_HTTPS.md)。

本机开发：`pnpm run dev` 仍绑定 `127.0.0.1`；Vite 开发代理把 `/api` 转到 `pnpm run dev:api` 启动的本机 API 服务，浏览器继续用同源相对路径。构建后可用 `pnpm run start` 在同一地址提供页面和接口。不要把 Vite 开发服务器直接当生产服务，也不要把 `server.allowedHosts` 设为 `true`。在实际访问设备上验证 HTTPS 信任、OPFS 与 Service Worker。

推荐新增文件职责：

| 文件 | 职责 |
| --- | --- |
| `src/translation.ts` | 前端请求、请求状态与正文快照一致性判断；不接触文章持久化。 |
| `src/main.ts` | 管理工作区模式、进入与返回、原文与译文展示、保存操作及上下文恢复，调用请求与 store 模块，响应编辑/切换事件；补充 Markdown 与数据说明。 |
| `src/types.ts`、`src/store.ts` | 定义 `saved_translation`，负责初始化、规范化、按练习更新及统一持久化与恢复。 |
| `src/backup.ts` | 完整与分析 JSON 均保留译文字段，复用现有 ZIP / JSON 备份链路。 |
| `src/styles.css` | 中右区域的整体替换、等宽大面积对照阅读、移动端、加载和错误状态。 |
| `server/translate.mjs` | 校验请求、调用适配器、统一错误响应；只接收正文。 |
| `server/providers.mjs` | Chat Completions 与 Responses 的请求和响应格式适配。 |
| `server/prompt.mjs` | 固定提示词 v1，供两个适配器共用。 |
| `tests/translation.test.ts`、`tests/translate-api.test.ts` | 快照状态及 API/适配器测试；沿用现有 `tests/*.test.ts` 运行入口。 |

服务端文件名是建议组织方式，可随现有部署工具调整，但前后端边界和接口契约保持一致。服务端不与 `src/store.ts` 共享 `AppState`，不读取浏览器数据。

## 4. 页面交互与状态

### 4.1 翻译阅读模式的位置与布局（0.5.0 已实现）

0.4.0 的 `#translationPanel` 嵌在编辑器下方；0.5.0 已将其提升为工作区级别的阅读容器：保留 `.overview-panel` 每日记录，将 `.main-panel` 与 `.side-panel` 原有区域整体替换为一个跨越中间、右侧两列的阅读容器。该模式不是浏览器全屏，也不覆盖顶部导航和全局存储状态。

布局示意（桌面）：

```text
原工作区： [每日记录] [编辑器 / 原文版本、标尺与统计] [版本链 / diff]
阅读模式： [每日记录] [ 返回入口 · 篇目与来源 · 翻译操作栏          ]
                     [ 原文（约 50%）      | 英文译文（约 50%）   ]
```

进入后，编辑器、历史原文阅读器、标尺、字数统计、保存版本、新练习操作、版本链与 diff 均隐藏，且从键盘焦点顺序和辅助技术可访问树中移除。原 DOM 可保留以方便恢复，但不能留空占位；阅读容器占满原中右区域。练习标签在阅读模式只显示当前篇目信息，切换篇目需先返回；左侧每日记录仍可用于切换记录。

阅读容器顶部显示与原入口一致的“返回编辑”或“返回版本阅读”，并显示日期、篇目、原文来源（草稿 / 所选历史版本）。正文为等宽两栏，左原文、右英文；操作包括复制、重新翻译、保存 / 覆盖、加载时取消，按状态显示。按钮旁保留“点击翻译后将当前正文发送给已配置的 AI 服务，可能产生费用。”的说明。仅查看保存文本不会上传正文。

桌面两栏使用原工作区可用高度，正文各自滚动，顶部返回与操作栏保持可见；长文自然换行，不截断，不强制同步滚动。阅读容器内容宽度达到 720px 时使用两栏，低于 720px 时纵向排列；不能沿用旧布局在中屏把译文或版本链挤到页面下方。纵向排列时原文在上、英文在下，正文自然展开、由页面滚动，操作栏可换行，避免多个小型滚动框。即使浏览器视口宽于现有 860px 断点，只要阅读区改为纵向排列，也需解除其固定高度与外层禁止滚动的限制；返回普通模式时恢复原布局。字体与行距沿用原正文阅读标准。

空白或超过现有 12,000 Unicode 码点上限的正文不可翻译；离线只禁用生成新译文，查看已保存译文、复制及手动保存仍可用。加载时禁用重复请求；阅读容器高度不足以容纳操作栏及正文时允许页面滚动，不能因独立滚动布局使返回或操作按钮不可见。状态变化通过 `aria-live="polite"` 报告，错误用 `role="alert"`；操作可用键盘完成。进入阅读模式后聚焦工作区标题，返回时恢复原入口焦点；编辑器的选区单独恢复，待用户再次聚焦编辑器时继续使用，不与入口争夺焦点；正文与译文均通过 `textContent` 和 `white-space: pre-wrap` 显示，不解析 HTML。

### 4.2 请求状态与工作区模式（0.5.0）

| 状态 | 页面行为 | 进入条件 |
| --- | --- | --- |
| `idle` | 编辑模式显示入口；阅读模式可显示已保存译文，或取消后的状态与重试入口 | 初始、切换正文、清理临时结果、取消完成后 |
| `loading` | 显示原文快照、加载状态和取消按钮 | 用户点击且正文非空 |
| `success` | 大面积显示原文与译文，支持复制、重新翻译和手动保存 | 收到有效且仍匹配当前正文的结果 |
| `error` | 显示原文快照、错误和重试按钮 | 当前请求失败且快照仍匹配 |

点击时生成递增的 `requestId`，记录 `entryId`、`mode`、`versionId | null`、`text` 快照和 `AbortController`。选择内容按以下规则：`mode=writing` 时用 `getActiveEntry(state).draft`；`mode=version` 时用当前选择的 `Version.content`，即使该版本是历史日期也允许翻译。发送前要求 `text.trim().length > 0`，但实际发送原始 `text`，保留换行和首尾空白。服务端再次校验。

输入变化、切换练习、切换版本、切换顶层视图、导入档案、存储重新加载和保存版本后的渲染，都调用统一的 `invalidateTranslation()`：中止请求、递增请求序号、清理临时翻译状态，保留已保存文本。若只是主题变化，不清理临时译文。响应到达时同时比较 `requestId`、`entryId`、`mode`、`versionId` 和正文全文；任一不匹配就丢弃结果。取消不保证上游停止计费，页面应避免暗示已撤销上游调用。

`renderInputState()` 目前只更新输入统计；翻译状态的清理需在编辑器 `input` 事件中显式调用，不依赖完整 `render()`。翻译区单独渲染，避免对译文组件调用 `innerHTML` 时丢失状态和焦点。视图切换只清理临时请求结果，回来若要生成新结果仍需重新点击；已保存译文独立从当前练习读取，不受 `invalidateTranslation()` 影响。

### 4.3 手动保存与已保存内容（0.5.0 已实现）

阅读工作区右栏分别标注“本次译文”和“本篇已保存译文”，从临时结果或 `DailyEntry.saved_translation` 读取，以纯文本展示并提供复制。同时存在时用“本次译文 / 已保存译文”切换，不在原编辑器下方再加小面板。刷新、重新打开或离线后，通过“查看已保存译文”进入阅读模式；历史版本模式下读取的也是本篇同一份保存文本。固定说明：“每篇只保留一份，再次保存会覆盖；已保存译文不一定对应当前正文。”已保存视图左栏展示进入时的原文，并明确其来源，不能标为保存译文的来源快照。

保存操作规则：

1. 仅 `translationDisplay=current`、`success` 且来源仍匹配当前 `entryId / mode / versionId / text` 的临时结果可保存；点击处理器再次校验，不能只靠按钮状态。离线不禁用本地保存与复制。切到保存视图时隐藏保存 / 覆盖按钮，复制按钮只复制右栏当前可见文本；不能把后台或隐藏的临时结果当作用户正在保存、复制的内容。
2. 当前练习无已保存文本时显示“保存译文”；有不同文本时显示“覆盖保存译文”。按钮旁告知覆盖旧文本，点击即保存，不增加确认弹窗。新结果产生、重试、取消或失败都不覆盖旧值。
3. 调用 `saveTranslation(state, entryId, text)` 后统一 `persistState(nextState)`，跟踪此次调用的持久化结果，仅更新该练习的 `saved_translation`；不调用 `saveVersion()`、不改 `draft / lastSavedContent / current_version_id / versions / created_at / updated_at`，避免把保存译文计作写作修改或改变练习排序。保存操作不触发翻译失效或网络请求。
4. 新增 store 操作对不存在的练习、空白文本返回原状态；按 ID 定位，不能在晚到事件中回退到其他活动练习。相同文本重复保存为无操作。正常结果保留内部换行与文本，不做 Markdown 或 HTML 转换。
5. 持久化进行中显示“正在保存译文”并禁用重复保存；按 8.2 节确认当前保存调用的可恢复写入成功后才报告“已保存”，降级显示“已保存到本地兼容存储”；无法确认可恢复写入时显示“译文保存失败，请重试”，保留临时结果并允许再次保存。字段相同但上次保存失败时仍允许重试 `persistState()`，不能因内存相等而禁用。不在文章数据中增加保存状态字段。保存中或全部失败时，内存字段属于已手动提交但尚未确认落盘的文本；右栏和返回后再次进入的入口也必须保留“正在保存 / 保存失败”提示，不能因字段非空就宣称已保存。若用户已经返回并清理了临时请求结果，再进入保存视图时，对尚未落盘的这份可见文本提供“重试本地保存”，仅重新提交已授权的字段，不重新调用 AI、不依赖旧临时结果，也不允许提交隐藏的新结果。后续成功的完整状态写入可完成这次已授权提交，但不得自动提交用户从未点击保存的新结果。
6. 已持久化且文本相同时显示“已保存”并禁用重复保存。已保存译文在重新翻译的加载、错误和取消期间仍可通过右栏标签查看；删除练习或导入完成后随新状态重新读取。原文编辑与版本保存不删除旧译文。

请求状态继续使用 `idle / loading / success / error`；保存反馈按练习 ID 与已提交文本保存在页面内存，跨阅读模式进出保留，导入 / 重置后清除；全局 `StorageStatus` 继续用于存储健康提示；单次保存成功以 8.2 节的结果为准，不能仅凭一条全局成功通知判断。完成启动恢复后从档案读取的保存文本视为已持久化；新点击的保存不能仅因内存字段已赋值就提前报告成功。

### 4.4 进入、返回与上下文恢复（0.5.0 已实现）

保留现有顶层 `view` 和原文来源 `detailMode`，另设仅存在于页面内存的 `workspaceMode: "document" | "translation"` 及阅读内容选择 `translationDisplay: "current" | "saved"`。不能把 `detailMode` 改成翻译后丢失草稿 / 版本来源，也不能因进入阅读模式就使刚创建的请求失效。阅读模式、返回上下文和滚动位置不进入 `AppState`、备份或本地存储；刷新后默认回到原写作工作区，再由用户主动查看保存文本。

| 操作 | 工作区与请求行为 |
| --- | --- |
| 点击“翻译成英文” | 先校验正文非空、码点长度上限与联网条件，捕获 `entryId / detailMode / selectedVersionId / text` 和返回上下文；切换阅读工作区后只发一次请求。左栏立即显示快照，右栏显示加载状态；成功或错误都保留阅读布局。 |
| 点击“查看已保存译文” | 仅字段非空时提供此入口；捕获当前草稿或所选版本正文供左栏参考，设置 `translationDisplay=saved`，直接本地读取右栏，不发请求、不要求联网。左栏无正文时显示“当前暂无原文”，仍允许阅读保存文本。 |
| 切换“本次译文 / 已保存译文” | 只切换右栏展示，不发请求、不覆盖存储、不改变原文选择；本次视图使用本次请求快照，保存视图使用进入时原文并标明可能不对应。加载、失败、取消时“本次译文”标签仍可显示对应状态；收到响应只更新本次内容，不把正在查看的保存视图强行切回。本次从未发起请求时不显示本次标签。切换本身不使仍有效的当前请求失效。 |
| 点击“重新翻译” / “重试” | 使用进入时保留且仍匹配当前练习与原文选择的来源，切换到本次译文并请求；旧保存文本仍可切换查看。空原文、超长或离线时禁用并说明原因；不可默认改用最新版本替代原选择。重新请求会清除此前未保存的本次结果，按钮旁事先说明；已保存文本不受影响。 |
| 点击“取消” | 中止当前请求并使迟到响应失效；保持阅读工作区和原文，显示“已取消”，可重试、查看旧保存文本或返回；不自动保存任何内容。 |
| 点击“返回编辑” / “返回版本阅读” | 中止请求，清理临时结果，恢复原中间与右侧区域、草稿 / 版本选择、编辑光标与选区、编辑器及页面滚动位置和入口焦点。离开时不自动保存译文或创建原文版本；未保存的译文随本次临时结果清理，返回按钮旁固定提示“返回后未保存的译文将丢失”，点击直接返回，不增加确认弹窗；已点击保存但正在落盘的操作继续完成。 |
| 左侧切换记录、回到今日、切换顶部视图 | 先退出阅读模式并清理临时请求，再执行原导航；不得把旧选择或滚动位置恢复到新练习，也不得自动翻译或自动打开新练习译文。 |
| 导入、重置、删除当前练习、OPFS 重新加载 | 使请求及返回上下文失效，恢复普通工作区，按新数据重新定位练习；不存在的版本或练习不再恢复。 |

进入阅读模式时先确保编辑器最新输入已同步到当前草稿，隐藏 DOM 或局部渲染不能丢失未保存草稿。返回时保持历史草稿原有的只读 / 解锁状态。保存译文引发的局部重绘、主题变化和存储状态更新不退出阅读模式、不重置正文滚动位置，也不重复请求。所有异步保存反馈通过页面会话序号、练习 ID 和目标文本匹配；离开、重进或导入后的旧回调不能修改新页面状态或重新写回旧档案。

请求加载、成功、错误与取消均占用同一个大阅读区；只有显式返回或上述导航 / 数据变更才退出。隐藏的编辑控件不能继续触发保存或修改；若通过外部数据变更导致正文与快照不匹配，沿用失效检查并退出到普通工作区，保存内容保留。

## 5. 前后端接口契约

`POST /api/translate`，同源、`Content-Type: application/json; charset=utf-8`。前端仅发送正文，服务商选择完全由服务端配置控制。

请求示例：

```json
{ "text": "今天下班后，我沿着河边走了一会儿。" }
```

成功响应：HTTP 200，`Cache-Control: no-store`：

```json
{ "translation": "After work today, I took a walk along the river." }
```

失败响应格式：

```json
{ "error": { "code": "UPSTREAM_TIMEOUT", "message": "翻译超时，请稍后重试。" } }
```

| HTTP | `code` | 触发条件与处理 |
| --- | --- | --- |
| 400 | `INVALID_INPUT` | JSON 无效、字段不符、正文空白；前端提示检查正文。 |
| 413 | `INPUT_TOO_LONG` | 超过请求体或正文字数上限；前端提示缩短正文。 |
| 429 | `RATE_LIMITED` | 本地限流或上游限流；提示稍后重试。 |
| 502 | `UPSTREAM_ERROR` | 上游错误、响应格式错误或译文为空；允许重试。 |
| 503 | `UPSTREAM_AUTH_ERROR` | 上游拒绝认证或授权；检查服务商地址和密钥。 |
| 504 | `UPSTREAM_TIMEOUT` | 上游超时；允许重试。 |
| 503 | `SERVICE_UNAVAILABLE` | 未配置或未完整配置 AI 接口；页面照常运行，点击翻译后提示先配置 AI 接口。 |

初始约束建议：请求体最多 32 KiB，正文最多 12,000 个 Unicode 码点，单请求超时 60 秒，最多 2 个并发调用和每分钟 10 次请求。服务端按实际字节数和码点数分别检查；上限作为服务器常量或环境变量，前端提供相同的预检查以尽早提示。超限错误不得回显正文。所有响应都设置 `Cache-Control: no-store`；对非 POST 方法返回 405。只接受 JSON；拒绝浏览器请求中不匹配站点 origin 的 `Origin`，并限制允许的 `Host`，降低局域网内跨站滥用风险。这些检查不等同于身份验证。

请求日志只记录时间、状态码、耗时、错误类别和随机请求 ID，不记录正文、译文、密钥或完整上游响应。不要把上游报错原文直接返回浏览器，因为其中可能包含敏感配置。服务端启动时校验 AI 配置；缺少或无效时继续提供站点，并在用户点击翻译后返回明确的 503 提示。若部署在反向代理后，应正确转发并校验外部 Host/Origin，不直接信任任意 `X-Forwarded-*` 值。

## 6. 服务商适配与配置

环境变量：

| 名称 | 示例或取值 | 说明 |
| --- | --- | --- |
| `AI_API_FORMAT` | `chat-completions` / `responses` | 启用翻译时选择；省略则默认 `chat-completions`。 |
| `AI_API_BASE_URL` | 服务商提供的地址前缀 | 启用翻译时必填；末尾不含 `/chat/completions` 或 `/responses`。不同服务可能有不同前缀。 |
| `AI_API_KEY` | 服务商密钥 | 启用翻译时必填；只在服务端读取。 |
| `AI_MODEL` | 所选服务提供的模型 ID | 启用翻译时必填；逐个服务核对实际支持的端点。 |

只允许 `https:` 上游地址；若明确使用局域网本地模型服务，可单独允许受信任的私网/环回 `http:` 地址，且不把密钥发送给不受信任地址。服务商配置在启动时固定；浏览器请求不能覆盖 URL、模型、提示词、请求头或接口格式。切换服务时改服务器配置并重启服务，无需改文章档案。

`chat-completions` 适配器发送 `model` 与 `messages`：一条固定 `system` 规则，一条带正文的 `user` 消息。解析 `choices[0].message.content`，只接受字符串内容；若 `finish_reason` 显示截断、过滤或非正常完成，则报错。`responses` 适配器发送 `model`、`instructions` 与 `input`；解析文本输出，检查响应状态完整性。两者首版均非流式，不发送 `temperature`、JSON 模式、工具、Web 搜索等可选参数。若某模型要求不同角色或特殊参数，新增明确适配规则，不默默降级成错误译文。

不把“OpenAI 兼容”理解为接口完全一致。DeepSeek 官方文档提供兼容调用示例；OpenCode Console 的模型表同时列出 Chat Completions 和 Responses 端点。部署时用选定模型做一次真实连通性检查，校验返回解析和翻译质量；自动化测试使用模拟上游，不消耗 API 额度。

## 7. 提示词与输出处理

提示词版本为 `translation-prompt-v1`，固定在服务端。完整内容沿用 [`TRANSLATION_PLAN.md` 的“翻译提示词 v1”](./TRANSLATION_PLAN.md#翻译提示词-v1)：忠实保留意思、事实、情绪、段落、数字和名称，使用自然日常英文；合适时允许少量常见俚语，避免公文腔和刻意堆砌。只返回英文译文。正文放在低优先级的用户输入中，作为待翻译数据；正文里出现的指令不应改变翻译任务。

服务端不对译文做自动回译或自动重写；这会增加费用和延迟，也可能掩盖模型问题。只做结构校验、首尾无意义空白清理和长度上限检查，内部换行保留。译文为空、被截断、含额外解释等质量问题：前两类视为错误，额外解释由人工评估样本推动提示词迭代。每次更改提示词版本时保留样本集并人工比较，避免为了口语化丢失原文含义。

## 8. 本地数据、PWA 与迁移（0.5.0）

### 8.1 数据模型与归属

在现有 `DailyEntry` 中新增一个字段，`AppState` 顶层和 `Version` 均不新增译文结构：

```ts
export interface DailyEntry extends Entry {
  versions: Version[];
  draft: string;
  lastSavedContent: string;
  saved_translation: string; // 默认 ""；本篇唯一一份手动保存的译文
}
```

归属通过其所在的 `DailyEntry.entry_id` 确定，不按日期匹配，不创建译文 ID、数组、历史记录或版本外键。草稿与所有历史版本的翻译共用这一字段；覆盖后不提供旧译文回溯。只保存文本是有意的取舍：无法可靠判断它对应哪次正文，因此页面始终明确标注为“本篇已保存译文”。

`createEntry()` 初始化为空字符串，其他创建入口继承默认值。`normalizeEntry()` 显式保留字符串字段；缺失、`null`、纯空白或其他类型统一归一为空字符串，不把对象强制转为文本。旧 v1 单篇迁移、v2 多篇恢复、分析 JSON 重建 diff 及 OPFS 读取都经过同一规范化规则。非空文本必须在往返后完整保留，空白文本视为没有译文。

`hasMeaningfulArticleData()` 与 `isEmptyPracticeEntry()` 增加对非空译文的判断；同时检查 `src/main.ts` 的 `isEmptyPractice()`，不能让仅有译文的练习被当作可复用的空练习。仅剩译文的练习也必须保留并参与存储升级，并可通过日期列表与练习标签重新访问；其缺席标记和写作统计仍按原文版本规则计算。写作统计与阅读流的筛选继续只基于原文，不把译文算作已写篇数或字数。删除练习和重置档案按原有行为一并删除译文，首期不提供独立译文编辑或删除入口。

### 8.2 复用原有持久化链路

`saveTranslation()` 负责更新内存状态，页面调用现有 `persistState()`：尝试写 `char300-lab-state-v2` 完整兼容快照，并在启用 OPFS 时排队写入 `char300/checkpoint.json`。复用原有写队列、降级、状态订阅和迁移校验，但补齐下面的完成结果与恢复规则；不建立译文专用存储 key、文件或数据库。`meta.json` 继续描述同一检查点格式。

译文保存走完整状态写入，不走 `persistDraftState()` 的草稿恢复日志。后续草稿输入、保存原文版本、恢复日志覆盖及其他 state 更新必须保留 `saved_translation`；OPFS 回读和升级前后的 `statesAreEquivalent()` 校验应覆盖该字段。存储失败时按 4.3 节保留当前译文并允许重试；未点击保存的临时结果始终不进入任何持久化状态。

**持久化结果与恢复规则（复核补充，0.5.0 已实现）：**

- 原 `persistState()` 返回 `void`，全局 `StorageStatus` 不能证明某一份译文已经写入。现已扩展为返回 `Promise<PersistenceResult>`，结果至少区分 `opfs-saved / local-fallback / save-error`，对应此次提交的完整快照；现有不需要等待的调用可继续忽略返回值；预期的存储异常均转换为结果并更新状态，不抛出无人处理的 Promise 拒绝。写队列合并快照时，只有实际写入快照仍包含该练习及目标译文才能确认这次保存成功；不能拿其他写入的成功状态代替。
- OPFS 启用时，等本次排队写入完成再决定结果。OPFS 失败而完整 `localStorage` 快照成功时，必须同时禁用本次会话的 OPFS 写入，并把现有 `char300-lab-opfs-upgrade-v1` 标记改为 `failed`，使下次启动跳过旧 OPFS 检查点、从本地完整快照恢复；不得继续保留 `upgraded` 后仍报告降级保存成功。这个标记是现有存储后端的健康标记，不是译文元数据。
- 降级标记必须在恢复安全的完整快照写入后成功落盘。若快照成功但标记失败，无法保证重启会选择新数据，按 `save-error` 提示并保留重试 / 导出能力。重新启用 OPFS 走现有升级流程，从当前完整档案写入并回读验证，不能先读取已过期的 OPFS 覆盖它。
- 启动时 `hydrateOpfsStorage()` 尚未完成期间暂不允许进入翻译或保存译文，入口显示“正在恢复本地档案”；成功、无 OPFS 或降级处理结束后再启用，防止用户刚保存的文本被晚到的启动恢复覆盖。
- 保存后仍可正常返回、切换记录或导出；排队保存持有提交快照，不能在完成回调中再次覆盖整个当前 `state`。导入 / 重置沿原队列写入新状态并使旧页面回调失效，确保最终落盘的是后提交的新档案。

### 8.3 备份、导出与兼容

本次为向现有数据添加默认可缺省的文本字段，保留 `schema_version: 2`、现有存储 key 与文件路径，不引入强制迁移或自动清空。兼容方向是“新版读取旧数据”；旧应用可能在规范化时丢弃新字段，不承诺用旧版导入再导出的译文完整性。

| 入口 / 输出 | 译文规则 |
| --- | --- |
| 完整 ZIP：`zhuzi-data.json` | 完整 `state.entries[].saved_translation`，包括仅有草稿或译文的练习；不受阅读流筛选限制。 |
| ZIP：`analysis/zhuzi-analysis.json`；单独轻量分析 JSON | 保留相同字段；仅原文版本的 diff 按既有方式精简，译文不生成 diff 或统计。 |
| ZIP / JSON 导入，包括裸 `AppState` | 规范化后按现有整档替换恢复；旧备份补空字段，导入旧档案会按替换语义清除当前译文，不合并。 |
| 当篇 Markdown、全部 Markdown、ZIP 中 Markdown | 有保存文本时在本篇原文版本之后追加一次 `### 本篇已保存译文`，附“可能不对应当前正文”说明后输出原文本；不为每个原文版本重复附加。全部导出时包含有译文的练习，不能仅复用只收录已有原文版本的筛选。 |
| `window.zhuzi.getBackupPayload()` / `exportJson()` | 随现有快照及分析 JSON 只读返回已保存字段，不暴露临时结果或增加写接口。 |
| 分析提示词与结构说明 | 说明该字段是英文参考文本，可能不对应当前正文，不应当作写作版本或纳入字数、修改量分析。 |
| 分享图片、总览、阅读流 | 保持原文展示与统计，不加入译文。 |

Markdown 的具体边界：`renderEntryMarkdown()` 已委托 `src/backup.ts` 的可测试渲染函数；没有原文版本时仍输出日期 / 篇目标题与已保存译文；无版本时不生成版本字数、修改量或迭代统计，不额外把未保存草稿加入 Markdown。有版本时保留现有“终版正文 + 版本列表”格式，仅追加译文。单篇 Markdown 按钮在“有原文版本或非空译文”时启用，全部 Markdown 与 ZIP 的 Markdown 清单使用相同筛选；仅有草稿且无译文时沿用旧导出行为。不要修改供阅读流、总览与图片共用的 `getWrittenEntries()` 来扩大 Markdown 范围。

用户已点击保存、但存储尚未完成或失败的字段可随手动备份导出以供恢复；这不代表本地写入成功。未点击保存的请求结果绝不导出。完整备份 JSON 是恢复依据，Markdown 仍只作阅读导出，不新增 Markdown 导入。保存后应验证完整 JSON、分析 JSON、ZIP 三种恢复入口的译文往返一致。

### 8.4 PWA 与隐私说明

- 生成翻译使用 POST，Service Worker 显式排除 `/api/`；不缓存翻译接口响应。用户手动保存到 OPFS / `localStorage` 的文本属于本地档案，离线可读、可复制和备份，与 HTTP 缓存独立。
- README 和页面本地存储说明应写明：“写作数据和手动保存的译文保存在当前浏览器；仅点击翻译时，将当前正文发送给所配置的 AI 服务。每篇可手动保存一份译文，随备份导出；未保存的结果关闭页面后消失。”同步替换当前“译文不随备份保存”的旧提示。
- 自建服务端仍不持久保存正文或译文，保存按钮不调用服务端。HTTPS 地址、设备与浏览器 origin 的存储边界与原文相同；更换地址前导出完整 ZIP，在新地址导入验证。

## 9. 测试与验收

### 自动化

1. 前端状态：空白正文不可请求；草稿和选中版本取值准确；点击只发一次请求；编辑、保存原文版本、切换练习/版本/视图、导入和 OPFS 重新加载使旧响应失效；取消后晚到结果不显示；复制内容为译文原文。
2. 服务端契约：正文上限、非法 JSON、缺配置、非 POST、错误 Content-Type、不同 Origin、并发与限流、超时、上游 401/429/5xx、空结果、截断/拒绝和异常响应形状都映射到约定错误，且不泄露密钥或正文。
3. 两个适配器：模拟上游验证请求字段、端点拼接、消息角色和结果提取。只测试本项目控制的行为，不把模拟译文的内容当作质量测试。
4. 译文存储：只有显式保存才写入；覆盖只保留一份，重复保存不创建版本，不改原文、版本统计和排序时间；同日多篇隔离，历史版本与草稿共用本篇字段。编辑、保存原文版本、切换和迟到响应不删除或误覆盖已保存文本。
5. 数据兼容：旧 v1 / v2、裸 state、完整与分析 JSON、ZIP 缺字段时补空；非字符串字段安全归一；新字段在初始化、草稿日志恢复、OPFS 读写、升级验证、完整与分析备份及只读 API 中均可往返。仅有译文的历史练习不被清理，删除 / 重置 / 整档替换按约定处理。
6. 持久化反馈：OPFS 排队期间不提前报告成功；OPFS 失败但本地快照与降级标记成功时显示降级状态，模拟重启确认不读回旧 OPFS；标记失败不报告成功；全部失败保留结果并可重试，同文本重试不被禁用；离线允许本地读取、复制和保存。Markdown 覆盖有版本、无版本但有译文、仅有草稿三种边界，按钮与清单一致，每篇仅附加一次译文；未点击保存的结果不进入任何导出。
7. 工作区模式：翻译与查看保存文本均整体替换中右区域；仅前者发送请求。进入模式不使自己的请求失效，返回与导航取消迟到请求；原文模式、选中版本、草稿、选区和只读 / 解锁状态均正确恢复；已保存视图无网络请求，右栏切换不误覆盖保存文本，复制以可见内容为准，保存视图不提供保存隐藏结果的按钮；响应不强制切换当前标签。保存中离开与导入后的旧回调不覆盖新页面或新档案。
8. 覆盖启动恢复期间的禁用状态、仅有译文练习的再次访问、保存失败后返回再进入的本地重试，以及页面 / 存储状态的异步竞争。
9. `pnpm run check` 继续通过；新增服务端测试接入 `pnpm test`，确保 CI 不需要真实 API 密钥。

### 手工验收

- 对照当前三列布局，确认点击翻译即合并原中间和右侧区域，标尺、编辑器、版本链、diff 完全退出显示及键盘焦点顺序；加载、错误、取消与查看保存文本均保持大阅读区。桌面两栏等宽且主要高度用于正文，长文可分别滚动；中屏不留版本链空位，窄屏上下阅读不截断。
- 从有未保存草稿和所选历史版本两种入口分别进入、返回，确认正文、选区、滚动位置、版本选择和历史编辑权限恢复；查看保存文本无需网络。查看已保存译文时始终有来源和“可能不对应”的提示，不要求自动判断原文是否已修改。返回、切换日期或顶层导航后，迟到响应不重新打开阅读区。

- 用真实选定服务翻译日常叙事、中英混写、多段落、引语、专名和含指令文字；译文忠实且自然，俚语使用适度，无前言和学习建议。
- 桌面和移动端可对照阅读、复制、手动保存及覆盖；刷新、重新打开与离线可回看已保存文本。先保存 A，再生成 B 未点击保存时刷新仍是 A；保存 B 后只剩 B。改动原文或查看历史版本时，始终提示保存文本可能与当前正文不同，不尝试在缺少来源信息时检测是否一致；慢请求中编辑/切换不会显示或保存错位译文。
- 在局域网访问设备上通过 `https://char300.com` 验证 `window.isSecureContext`、OPFS 状态、Service Worker 注册、离线写作及从旧 origin 迁移档案；部署验收需要实际设备和受信任的 Caddy 根证书。
- 查看浏览器开发者工具与服务器日志，确认仅点击时上传当前正文，翻译响应不被缓存，密钥不出现在网页资源和日志中。
